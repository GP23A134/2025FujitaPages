# データ更新・移動・追加の仕様

## 作業開始時の確認プロンプト

データを更新する前に、次の内容を確認してください。

```text
対象データの更新内容を確認します。
1. 追加するクラスの種類（上位・中間）とラベルを決める
2. 移動する対象クラスまたは中間クラスを決める
3. 移動先の親クラスを決める
4. 既存のインスタンスと対象クラスの関係は変更しない
5. 親子関係は「子クラスID → 親クラスID」で登録する
6. 循環する親子関係や重複した関係を作らない

内容を確認したら、class-list.tsv と class-relation.tsv を保存し、
ClassDataUpdate を実行してデータを更新してください。
```

この確認内容と操作単位は、`edit.html` / `edit.js` の編集画面を基準にします。

## 編集画面とファイル更新の対応

| 編集画面の操作 | 保存される内容 |
|---|---|
| 上位・中間クラスを追加 | `class-list.tsv` に新しい行を追加 |
| 対象クラスを中間クラスへ移動 | 対象クラスの既存関係を削除し、新しい親との関係を追加 |
| 中間クラスを上位クラスへ移動 | 中間クラスの既存関係を削除し、新しい親との関係を追加 |
| 親クラスを変更 | 対象の子クラスに対する既存関係をすべて削除し、新しい関係を1件追加 |
| 未分類へ移動 | 上位クラスごとに「未分類」中間クラスを作成または再利用し、その配下へ移動 |
| 編集内容を保存 | `class-list.tsv` と `class-relation.tsv` を出力 |

対象クラス自体の追加は編集画面では行いません。対象クラスやインスタンスを新規取得する場合は、
SPARQLの取得結果を更新し、`DataIntegrate` を実行します。

## 更新・移動・追加の基本ルール

- 追加できるのは上位クラスと中間クラスです。
- 新規クラスのIDは、既存の最大番号の次から採番します。欠番は再利用しません。
- 編集画面で未保存の変更がある状態で画面を移動・更新すると、保存確認が表示されます。
- 変更後は、クラス一覧・親子関係・ツリー表示を同時に更新します。
- 同じ対象クラスを複数回選択しても重複移動しません。
- 移動した対象クラス・中間クラスは、移動後に選択状態を解除します。
- 自分自身または自分の子孫を親に指定する循環移動は禁止します。
- 親子関係は必ず「子 → 親」の向きで記録します。

## 入力ファイル

このフォルダーのTSVを編集してから、`ClassDataUpdate`を実行します。

## class-list.tsv

UTF-8、タブ区切りで、ヘッダーは次のとおりです。

```text
種類	ID	ラベル
```

種類は `top`、`middle`、`class`（または日本語の上位クラス・中間クラス・対象クラス）を指定します。IDを空欄にすると、既存IDの最大番号の次に自動付与します。

## class-relation.tsv

UTF-8、タブ区切りで、ヘッダーは次のとおりです。

```text
子クラスID	親クラスID
```

IDは `c_00001` のような短縮形でも、完全URIでも指定できます。ファイルに記載した関係が、統合後のクラス間関係になります。

## 実行

```powershell
java -cp "bin;lib/*" ClassDataUpdate
```

コンパイル手順やmacOS/Linuxでの実行方法は[`java/README.md`](../../java/README.md)を参照してください。

出力先は `data/integrated-data/` の `class-data.json`、`target-class-data.json`、`middle-class-list.json`、`top-class-list.json` です。`instance-class-data.json` は変更しません。
