# クラス分類の差分JSONをAIに作成させるプロンプト

クラス分類の変更を、既存データへ適用する差分JSONとして作成します。全クラス一覧や全親子関係を再出力しません。

## AIに渡す情報

全データを添付する必要はありません。変更対象を特定し、誤った親子関係を避けるため、変更に関係する範囲の次の情報を渡してください。

- 対象クラスまたは中間クラスのID、種類、ラベル
- 移動対象の現在の親子関係
- 移動先の親クラスのID、種類、ラベル
- 同名クラスの新設を判断するため、候補となる上位・中間クラスのIDとラベル
- 新しい上位・中間クラスを作る場合は、その親クラス

IDや現在の関係が分からず、渡された情報からも一意に確認できない場合は、推測せず確認事項を返してください。対象クラスのラベルは差分に含めません。

## AIへの指示

渡された現在データの抜粋とユーザーの変更指示をもとに、`ClassDataUpdate`が既存データへ適用できる差分JSONを作成してください。差分JSONは`data/input/class-update.json`として保存して実行します。

### 操作の表し方

- 新しい上位・中間クラスは`addClasses`に追加します。新規IDは`new-t_1`、`new-m_1`のような一意の一時IDにします。`type`は`top`または`middle`、`label`は空にしません。
- 上位・中間クラスの名称変更は`renameClasses`に記載します。対象クラスの名称変更はこの差分では行いません。
- クラスの移動は`removeRelations`に現在の親子関係を、`addRelations`に新しい親子関係を記載します。移動対象以外の関係は差分に含めません。
- ある中間クラスの直接の子をすべて別の親へ移すときは、子ごとの関係を列挙せず`moveChildren`を使えます。`from`が移動元の中間クラス、`to`が移動先の上位または中間クラスです。この操作は直接の子だけを移動し、孫以下の関係は維持します。
- クラスを削除する場合は`removeClasses`にIDを指定します。削除前にそのクラスが持つ親子関係を`removeRelations`または`moveChildren`で解消してください。関係が残るクラスは削除できません。
- 対象クラスを新しい中間クラスへ移す場合は、中間クラスの追加、その中間クラスと親との関係追加、対象クラスと新しい中間クラスとの関係追加を行います。
- 対象クラスは中間クラスまたは上位クラスに直接所属できます。中間クラスは上位クラスまたは別の中間クラスに所属できます。
- 親子関係の向きは「子 → 親」です。各関係の`child`が子、`parent`が親です。
- 対象クラスは1つの親に所属させます。中間クラスにも所属先を設定し、循環を作らないでください。

### 分類ルール

- 既存の「未分類」上位クラスを利用し、新しい「未分類」クラスや中間クラスを作りません。「未分類」上位クラスの下にも中間クラスを配置せず、未分類の対象クラスを上位クラスへ直接関連付けます。
- 中間クラスを新設または改名しようとするとき、同じラベルの上位クラスが既にあれば、その中間クラスを作成・改名せず、対象クラスを該当する上位クラスに直接関連付けます。
- この同名ルールは新設・改名時に適用します。既存データにすでにある同名の上位・中間クラスは、明示的な指示がない限り削除・改名・移動しません。既存分も整理する指示か判断できない場合は確認してください。既存の同名中間クラスを上位クラスへ統合する指示がある場合は、対応する上位クラスへ`moveChildren`で直接の子を移し、旧親子関係を削除し、子がなくなった中間クラスを`removeClasses`で削除します。
- 既存クラスのIDと、変更指示がないラベル・関係は維持します。
- インスタンスID、インスタンスと対象クラスの関係、対象クラスのラベルは差分JSONに含めません。
- 削除する関係は、現在データに存在する親子関係と完全に一致させます。重複したID・関係、自己参照、循環を作らないでください。

## 出力形式

確認事項がなければ、次の6配列をすべて含むJSONオブジェクトだけを出力してください。変更しない配列は空配列にします。説明文、Markdownコードフェンス、コメント、末尾カンマは付けません。

```json
{
  "addClasses": [
    { "type": "middle", "id": "new-m_1", "label": "新しい中間クラス" }
  ],
  "renameClasses": [],
  "removeRelations": [
    { "child": "c_00001", "parent": "m_00001" }
  ],
  "addRelations": [
    { "child": "new-m_1", "parent": "t_00001" },
    { "child": "c_00001", "parent": "new-m_1" }
  ],
  "moveChildren": [],
  "removeClasses": []
}
```

- `addClasses`の要素は`type`、`id`、`label`を含めます。追加できるのは上位・中間クラスです。
- `renameClasses`の要素は`id`、`label`を含めます。
- `removeRelations`と`addRelations`の要素は`child`、`parent`を含めます。
- `moveChildren`の要素は`from`、`to`を含めます。
- `removeClasses`の要素は`id`を含めます。
- 既存IDは正式URIまたは短縮IDを使用できます。一時IDは新設クラスの参照に使います。
- 全データや変更していない関係を出力しないでください。
- 必要な変更情報が不足している場合、またはユーザーの指示が曖昧な場合はJSONを作らず、確認事項を箇条書きで返してください。
