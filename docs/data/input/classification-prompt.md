# 分類入力TSVを作成するためのプロンプト

次のルールで、分類変更用の2つのTSVを作成してください。

## class-list.tsv

- ヘッダーは `種類<TAB>ID<TAB>ラベル`
- 種類は `top`、`middle`、`class` のいずれか
- 新規クラスはIDを空欄にする
- 既存クラスは完全URIまたは `t_1`、`m_1`、`c_1` の形式で記載する

## class-relation.tsv

- ヘッダーは `子クラスID<TAB>親クラスID`
- クラス間の所属関係を1行ずつ記載する
- 対象クラス・中間クラス・上位クラスのすべてを指定できる
- インスタンスIDは記載しない

入力内容に不明点がある場合は、TSVを生成せず、問題点を箇条書きで示してください。

## 作成時の注意事項

- 既存クラスのIDは、元データにある完全URIをそのまま使用する。
- 新規クラスのIDは、既存クラスの完全URIと衝突しないようにする。
- 短縮IDと完全URIを同じクラス定義内で混在させない。
- TSVの区切り文字は、文字列 `` `t `` ではなく実際のタブ文字を使用する。
- `class-list.tsv` のヘッダーは `種類<TAB>ID<TAB>ラベル` とする。
- `class-relation.tsv` のヘッダーは `子クラスID<TAB>親クラスID` とする。
- クラスIDと親クラスIDの組み合わせは重複させない。
- 対象クラスは、原則として親クラスを1つだけ持たせる。
- 上位クラスや中間クラスを子クラスにしない。
- 自己参照や親子関係の循環を作らない。
- 所属クラスが0件の上位クラスと中間クラスは作成しない。
- 既存の親子関係を変更する場合は、変更前の関係を削除してから新しい関係を追加する。
- Java処理後、入力TSVは `data/input/processed` へ移動されるため、再実行時は入力フォルダへ戻す。
