# 分類更新JSONを作成するためのプロンプト

分類変更の内容から、`ClassDataUpdate`で読み込める`class-update.json`を作成してください。

## JSON形式

```json
{
  "classes": [
    { "type": "top", "id": "t_1", "label": "上位クラス" },
    { "type": "middle", "id": "new-m_1", "label": "新しい中間クラス" },
    { "type": "class", "id": "c_00001", "label": "対象クラス" }
  ],
  "relations": [
    { "child": "new-m_1", "parent": "t_1" },
    { "child": "c_00001", "parent": "new-m_1" }
  ]
}
```

## 作成ルール

- `classes`には上位・中間・対象クラスを含め、それぞれ`type`、`id`、`label`を指定する。
- `type`は`top`、`middle`、`class`のいずれかにする。
- 既存クラスのIDは元データの完全URIまたは短縮IDを使う。
- 新しいクラスには`new-t_1`、`new-m_1`のような一時IDを付ける。番号は既存の最大番号より大きくする。
- `relations`にはクラス間の関係を`{ "child": "...", "parent": "..." }`として記載する。
- 親子関係は「子 → 親」の向きにし、対象クラスの親は原則1つにする。
- インスタンスIDやインスタンスと対象クラスの関係は含めない。
- 同じ種類・ラベルのクラス、重複したIDや関係、自己参照、循環関係を作らない。
- 所属先のない上位クラス・中間クラスを作らない。
- 既存の親子関係を変更する場合は、変更前の関係をJSONから削除して新しい関係を記載する。
- 入力内容に不明点がある場合はJSONを作成せず、確認事項を箇条書きで示す。

JSONのキーと文字列値はダブルクォートで囲み、コメントや末尾カンマを含めないでください。
