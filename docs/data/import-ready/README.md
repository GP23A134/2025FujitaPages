# 読み込み用データ

`class-instance-data.json`は、`data/query-results/base/`にある3つのSPARQLクエリ結果を1つにまとめたデータです。クラス階層とインスタンス所属を別の関係として格納する共通形式です。元のクエリ結果には上位クラス・中間クラスの親子関係がないため、`classRelations`は空です。

アップロード画面では、このファイルとクラス階層を記録したJSONを同時に選択できます。クラスIDを照合し、階層側のクラス情報と親子関係を統合して読み込みます。

```json
{
  "classes": [{ "id": "...", "label": "...", "type": "class" }],
  "instances": [{ "id": "...", "label": "..." }],
  "classRelations": [{ "child": "...", "parent": "..." }],
  "instanceClassRelations": [{ "instance": "...", "class": "..." }]
}
```


IDはクエリ結果のURIをそのまま使用しています。今回のデータには対象クラス229件、インスタンス2,315件、クラス階層関係0件、所属関係2,314件があります。関係の参照先はすべてこのJSON内に含まれています。クラスはすべて`type: "class"`です。

## 例外データ

通常データに含めていない例外は[`exceptions.json`](exceptions.json)にまとめています。

| 種類 | 件数 | 内容 |
|---|---:|---|
| ラベルなしクラス | 1 | クラスID `https://kozaki-lab.jp/REFV-KG/class/st_14` はありますが、ラベルがありません。 |
| クラスなしインスタンス | 1 | `https://kozaki-lab.jp/REFV-KG/data/st_10221_1`（遠藤初子議員）は所属クラスがありません。 |

クラスラベルのクエリ結果にはクラスIDもない空行が1件あります。これはクラスとして登録できるIDがないため、例外ファイルには個別のクラスとして含めていません。

## 現行システムから分けたデータ

2ファイルをアップロードして統合する動作を確認できるよう、現行システムの生成データも同じ形式に分けてあります。アップロード画面で2ファイルを同時に選択してください。

| ファイル | 内容 |
|---|---|
| [`current-system-class-instance-data.json`](current-system-class-instance-data.json) | 対象クラス、インスタンス、インスタンスの所属関係 |
| [`current-system-class-hierarchy-data.json`](current-system-class-hierarchy-data.json) | 上位・中間・対象クラスとクラス間の親子関係 |

クラス・インスタンス側には対象クラス11,913件、インスタンス19,998件、所属関係19,998件があります。階層側には上位クラス13件、中間クラス142件、対象クラス11,913件、親子関係12,055件があります。両方のファイルに対象クラスが含まれますが、クラスIDで対応付けるため、統合後に重複しません。
