# AIチャットの構成

編集画面は `main.js` を入口にし、機能ごとのESモジュールを同じフォルダから読み込みます。`edit.html` は `main.js` だけを読み込み、依存するモジュールは `main.js` の `import` で解決します。

## モジュール

| ファイル | 担当 |
| --- | --- |
| `main.js` | 画面初期化、会話状態、送信フロー、モジュール間の連携 |
| `api-client.js` | OpenAI Responses APIへのHTTP通信とHTTPエラーの変換 |
| `id-codec.js` | クラスIDの短縮と、応答IDの復元 |
| `request-planner.js` | 依頼本文の生成、対象範囲の組み立て、大きな依頼の分割 |
| `response-handler.js` | AI応答の形式検証、提案操作の検査、追加データ要求の解決 |
| `conversation-store.js` | 会話履歴のブラウザー保存・復元 |
| `conversation-view.js` | 履歴一覧とメッセージ吹き出しの描画 |
| `proposal-preview.js` | 変更案のプレビュー、操作選択、ナビゲーション、適用 |

## 送信フローを `main.js` に残す理由

`main.js` の送信処理は、画面の確認、対象範囲、分割リクエスト、応答の統合、会話履歴の更新を順番に調整します。各機能モジュールをつなぐ役割があるため、現段階ではオーケストレーションとして `main.js` に置いています。通信、送信データの計画、応答検証などの個別処理は、それぞれのモジュールに分離しています。

この処理をさらに分割する場合は、送信全体の状態やキャンセル処理、分割結果の統合を一つのオーケストレーターに移し、画面表示と編集状態は引数やコールバックで渡す形にします。依存関係が明確になり、単独で確認できる境界ができた段階で行います。

## 送信コストの抑制

- 分割評価の結果は、モデル・指示文・依頼文・データ版・対象範囲が一致した場合に再利用します。内容が変わった範囲だけ再送し、同一データの追加相談では保存済みの全体要約を使います。
- 全体参照の分析要約も保存します。同じデータ版・選択範囲での通常の追加相談は要約だけを送り、データ変更、範囲変更、構造の再確認、明示的な再分析依頼では全体スナップショットを送り直します。
- Responses APIにはモデルと固定システム指示から作った安定した`prompt_cache_key`を渡し、同じモデル・指示の入力でプロンプトキャッシュを利用しやすくします。キャッシュのヒットはAPIの使用量で確認します。
- 出力上限は通常5,000、分割チャンク3,000、分割結果の統合4,500トークンです。依頼の内容に応じて不足が起きないか、実際の使用量を見ながら調整します。
- 回答は必要な結論と根拠に絞ります。詳しい説明を求められた場合や、変更案の安全な操作を示す場合に必要な情報は省きません。
- 応答JSONでは`m/p/q/d`や`i/t/s/r/o`などの短縮キーと、短い操作種別コードを使います。受信後にブラウザー内で従来の`message`、`proposals`、`operations`形式へ展開するため、画面表示・提案検証の内部形式は変わりません。
- 固定ルールは`web/data/config/ai-system-prompt.md`にまとめ、送信ごとの範囲・分割・提案方針は共通ルールの後ろに追加指示として渡します。APIに送る前にこの指示をデータJSONから分離するため、同じモードのチャンク間で安定したプロンプト先頭を保てます。一般ルールの重複を減らし、返答形式もAPIスキーマの短縮キーに合わせます。

## 送信と処理中の表示

- 実行ボタンを押した時点から経過時間を計り、準備中は「依頼内容を準備しています」と秒数をチャット欄に表示します。送信後も作業段階と秒数を表示します。
- 表示する主な段階は、送信内容の確認待ち、AIに送信中、結果を処理中、分割処理中、結果を統合中、変更を適用中です。分割処理は完了数／全体数を表示します。
- 分割ごとの回答と全体統合を別工程として扱います。結果統合に失敗した場合は分割ごとの回答を残し、部分結果であることを知らせます。

## 提案プレビュー

- 応答の操作形式、ID、変更可能範囲、移動先、同じ親への移動などを検査し、安全でない操作を除外します。同名クラスが複数あるときは親階層から再利用先を一意に決め、決められない操作を除外します。親IDまたは表示上の親経路が変わらない移動は除外し、変更一覧には変更前後の親経路を表示します。
- 変更前後のツリーでは操作種別ごとに色枠を表示します。追加の矢印は両ツリーの間に置く「＋ 追加」マーカーから新しいクラスへ引きます。
- 変更一覧は初期状態で閉じています。変更後のクラスにカーソルを合わせると、変更前のクラスと移動矢印も強調表示します。
- 提案を選択してプレビューした後、利用者が適用した場合だけ編集状態を更新します。インスタンスと対象クラスの関係は変更しません。
