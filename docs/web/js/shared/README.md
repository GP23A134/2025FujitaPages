# 共通処理

閲覧画面と編集画面で共用する階層ツリー、データ取り込み、作業データ保存の処理です。ページ固有の表示や編集操作は各画面のフォルダに置きます。

## ファイル

| ファイル | 担当 |
| --- | --- |
| `class-types.js` | IDと明示型からクラス種別を一元判定し、画面初期化前に作業データを正規化 |
| `hierarchy-validation.js` | クラス階層の親子・種別・循環・所属漏れを共通検証 |
| `tree.js` | 階層モデル、ツリー描画、対象クラスの行配置、展開位置の保持など共通関数 |
| `data-upload.js` | JSON取り込み、参照・循環の検証、作業データへの追加・置換 |
| `data-workspace.js` | IndexedDBへのタブ別作業データと取り消し履歴の保存、初期データ版管理 |

## データ取り込み

取り込みは最大2ファイル、合計50MBまでです。親子関係の重複、参照先不在、階層種別の不整合、循環、所属漏れなどを編集時と同じ検証関数で確認します。分割ファイルの読み込み中は不足する親を保留し、結合後の階層全体で所属を確認します。

クラス種別は明示された`type`を優先し、ない場合は既存IDの接頭辞から一度だけ推定します。画面間で種別情報を共有し、ラベルが「未分類」の上位クラスも読み込み時にIDを書き換えません。

アップロードした作業データと取り消し履歴はIndexedDBにタブごとに保存します。同じタブで編集画面・閲覧画面を移動または再読み込みしても復元し、別タブの作業データとは分離します。初期データはデータ全体の版指紋で管理し、同梱データが更新されると「初期状態」も更新します。

## 読み込み方

`index.html`と`edit.html`で`class-types.js`と`hierarchy-validation.js`をデータ復元処理より先に読み込みます。共通関数は通常のブラウザースクリプトから使えるよう`window`に公開します。

閲覧・編集のツリーDOMはこのモジュールで共通化し、各画面のモジュールが検索結果、操作ボタン、選択表示を追加します。階層線やカードの見た目は`web/css/tree-structure.css`と`web/css/tree-appearance.css`で調整します。
