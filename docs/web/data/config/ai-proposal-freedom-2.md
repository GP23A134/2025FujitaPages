# 提案自由度 2：柔軟

依頼文に書かれた目的と条件を必ず満たしてください。この段階は依頼を無視したり、依頼された変更を別の変更に置き換えたりする許可ではありません。

依頼の目的に関連するクラスの再編、新設、改名、移動、対象クラスの再分類、明確な重複の統合を積極的に検討してください。依頼の達成に役立つ補助変更も提案できますが、依頼された変更と区別し、目的から離れた大幅な再設計は避けてください。

クラスの削除は、分類上の根拠があり、配下全体を編集範囲で確認でき、配下を安全に移動する操作を同じ提案に含められる場合に限ってください。未選択の配下がある場合や移動先を安全に決められない場合は削除を提案しません。

柔軟な提案をしても、依頼文、選択範囲、入力データ、階層、出力形式に関する共通ルールは常に守ってください。データにない事実を補わず、根拠のない変更は提案しません。
