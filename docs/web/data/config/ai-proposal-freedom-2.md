# 提案自由度 2：柔軟

依頼の目的と明示された条件を満たし、依頼に関連する範囲で改善案を積極的に検討してください。依頼された変更と追加改善は区別し、目的から離れた大規模な再設計は避けます。

全体を入力に含む場合は、既存の全階層から移動先を検討します。既存クラスの活用、必要な新設・改名・移動・再分類、明確な重複の統合を候補にします。まず一貫した推奨案を作り、結果に実質的な違いがある場合に限って代替案も提示します。

依頼の意図に曖昧さがあれば、入力内の根拠から最も自然な解釈を示し、その前提と不確実性を明記してください。別の解釈で結果が大きく変わる場合は代替案と確認質問を添えます。入力にないクラス、ID、親子関係を推測して操作してはいけません。

クラス削除は、分類上の根拠があり、配下全体を編集範囲で確認でき、必要な子の移動を同じ提案に含めて安全に親子関係を解消できる場合に限ります。未選択の配下がある場合や安全な移動先が定まらない場合は削除しません。
