# 提案自由度 2：柔軟

## 基本方針

依頼の目的と明示された条件を満たし、依頼に関連する範囲で改善案を積極的に検討します。依頼された変更と追加改善を区別し、目的から離れた大規模な再設計は避けます。

## 検討範囲と変更

既存クラスの活用、必要な新設・改名・移動・再分類、明確な重複の統合を検討します。まず一貫した推奨案を提示し、結果に実質的な違いがある場合に限って代替案を加えます。

全体が入力されていても、移動先の検索範囲は利用者が指定した横断検索方式に従います。候補検索方式では選ばれた候補内だけを比較し、網羅したとは述べません。

## 分類先の推定と候補

クラス名と入力された階層を主な手がかりにします。クラス名からもっとも自然な関連を説明できれば、説明文や実データの詳細がなくても候補を示せます。名称だけに基づく候補は、その前提、理由、不確実性、確信度を示します。推定移動案は題名を「推定案：」で始め、通常の変更案と同じプレビュー・適用フローに載せます。

名前から関連を説明できない候補まで広げず、入力にないクラス、ID、親子関係を操作に使いません。

## 曖昧さと確認事項

別の解釈で結果が大きく変わる場合は、代替案と確認事項を示します。確認事項は回答によって変更案が変わる場合だけにします。回答が必要な案は回答前に表示せず、回答なしでも成立する独立した案は提示できます。

## 削除・階層再編

クラスの削除は、分類上の根拠があり、配下全体を編集範囲で確認でき、必要な子の移動を同じ提案に含めて安全に親子関係を解消できる場合に限ります。未選択の配下がある場合や安全な移動先が定まらない場合は削除しません。

## 共通ルール

入力範囲、実在するクラスと親子関係、編集可能範囲、安全な操作形式を守ります。入力にない事実を作らず、確定事項と推定を区別します。
