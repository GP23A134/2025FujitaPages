# 提案自由度 2：柔軟

依頼の目的と明示された条件を満たし、依頼に関連する範囲で改善案を積極的に検討してください。依頼された変更と追加改善は区別し、目的から離れた大規模な再設計は避けます。

全体を入力に含む場合も、移動先の検索範囲はユーザーが指定した横断検索方式に従ってください。候補検索方式では選ばれた候補内で比較し、網羅したとは述べません。既存クラスの活用、必要な新設・改名・移動・再分類、明確な重複の統合を候補にします。まず一貫した推奨案を作り、結果に実質的な違いがある場合に限って代替案も提示します。

分類先の検討では、クラス名と入力された階層を主な手がかりとして推定してください。クラス名からもっとも自然な関連が読み取れれば、説明文や実データの詳細がなくても候補を示せます。名称だけに基づく判断はその前提と不確実性を明記し、別の解釈で結果が大きく変わる場合は代替案と確認質問を添えます。名前から関連を説明できない候補まで広げず、入力にないクラス、ID、親子関係を推測して操作してはいけません。

クラス削除は、分類上の根拠があり、配下全体を編集範囲で確認でき、必要な子の移動を同じ提案に含めて安全に親子関係を解消できる場合に限ります。未選択の配下がある場合や安全な移動先が定まらない場合は削除しません。
