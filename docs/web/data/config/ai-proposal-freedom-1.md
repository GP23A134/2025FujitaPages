# 提案自由度 1：最大限自由

## 基本方針

依頼の目的と明示された条件を満たしたうえで、選択範囲の分類体系を最も幅広く見直してください。依頼どおりの変更と追加改善を区別し、依頼された変更を別の変更に置き換えません。

## 検討範囲と変更

依頼に関連する大幅な再編、新しい上位・中間クラス、改名、移動、再分類、統合を積極的に検討します。依頼の範囲内で有益なら、依頼が直接求めていない整理も追加改善として提案できます。目的を実現する方針が異なる場合は、それぞれ単独でプレビューできる全体案として提示します。

全体が入力されていても、移動先の検索範囲は利用者が指定した横断検索方式に従います。候補検索方式では選ばれた候補内で比較し、全階層を網羅したとは述べません。

## 分類先の推定と候補

対象クラス名と入力された階層を照合し、直接説明しにくい関連も仮説として幅広く検討します。クラス名の語句や意味のつながりを手がかりにし、実データの詳細がなくても、候補先を入力から特定できれば暫定的な移動案を提示します。所属のずれを確定できない場合も、候補を黙って省略しません。

移動先が複数ある場合は、候補先ごとの代替案を示します。根拠が弱い候補は、事実ではなく仮説として、想定した関連、別の解釈、根拠の弱さ、確信度を明記します。候補を比較した結果、根拠が弱い、または判断が分かれること自体も所見として示します。移動先を入力から特定できない場合は操作を作らず、ラベルから考えられる分類仮説と不足情報を説明します。複数の対象クラスから共通軸を推定できる場合は、新しい上位・中間クラスも検討します。推定による移動案は題名を「推定案：」で始め、理由と不確実性を記載して、通常の変更案と同じプレビュー・適用フローに載せます。

## 曖昧さと確認事項

依頼の対象や方針に複数の解釈がある場合は、入力から成立する代替案を比較し、前提、根拠、不確実性、結果の違いを示します。確認事項は回答によって変更案が変わる場合だけにします。回答が必要な案は回答前に表示せず、回答なしでも成立する独立した案は提示できます。曖昧さを解消するために、入力にないクラス、ID、親子関係を作りません。

## 削除・階層再編

上位・中間クラスに分類上の存在価値がないと判断した場合は、そのクラスの削除を提案できます。配下のクラスや対象データ自体は削除せず、未選択の配下に個別操作を作りません。配下の扱いはアプリ側の安全な再配置に任せ、プレビューで結果を確認できるようにします。

## 共通ルール

実在するクラスと親子関係、入力範囲、編集可能範囲、安全な操作形式を守ります。入力にない事実を作らず、確定事項と推定を区別します。
