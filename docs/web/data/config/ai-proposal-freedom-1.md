# 提案自由度 1：最大限自由

依頼の目的と明示された条件を満たしたうえで、選択範囲の分類体系を最も幅広く見直してください。依頼の変更を別の変更に置き換えず、依頼どおりの案と追加改善を区別します。

全体を入力に含む場合も、移動先の検索範囲はユーザーが指定した横断検索方式に従ってください。候補検索方式では選ばれた候補内で比較し、全階層を網羅したとは述べません。大幅な再編、新しい上位・中間クラス、改名、移動、再分類、統合を積極的に検討し、目的を実現する方針が異なる案は、それぞれ独立して適用できる全体案として提示してください。依頼の範囲内で有益なら、依頼が直接求めていない整理も追加改善として提案できます。

依頼の意図や分類に曖昧さがある場合は、入力から成立する複数の解釈を案にして比較します。各案の前提、根拠、不確実性、結果の違いを示し、選択に役立つ確認質問を添えてください。曖昧さを解消するために、入力にないクラス、ID、親子関係を作ってはいけません。

根拠が十分でないことだけを理由に候補を省略せず、クラス名から直接関連を説明できない候補も含め、分類上検討価値のある移動先や新しい分類軸を幅広く探索してください。クラス名同士の語句や意味のつながりを手がかりにしつつ、それを超える候補は事実ではなく仮説として示し、根拠の弱さ、想定した関連、別の解釈、確認が必要な点を明記します。既存の移動先を一意に選べない場合は、入力中に実在する候補ごとの代替案を示します。複数の対象クラス名から共通軸を推測できる場合は、新しい上位・中間クラスの案も検討し、対象範囲内で操作可能なクラスに限って追加・移動操作を組み立てます。候補を比較した結果、根拠が弱い、または判断が分かれること自体も所見として示し、候補を黙って除外しないでください。

個別の実体内容や追加の分類根拠が入力されていないことだけを理由に、所属判断や変更案を保留しないでください。対象クラス名を入力中の上位・中間クラス名および階層と照合し、関連しそうな移動先があれば、所属のずれを確定できなくても暫定的な移動案として提示します。候補先が複数なら候補ごとに代替案を作り、各案の仮定と不確実性を明記してください。実在する移動先を入力から特定できない場合は、移動操作を作らず、ラベルから考えられる分類仮説と不足情報を説明します。

上位・中間クラスに分類上の存在価値がないと判断した場合は、配下のクラスや対象データを削除せずに、そのクラスの削除を提案できます。配下の再配置はアプリが行うため、未選択の配下に個別操作を作らず、プレビューで結果を確認できるようにしてください。

自由な案を出しても、入力範囲、実在するクラスと関係、安全な操作形式などの共通ルールは守ってください。
