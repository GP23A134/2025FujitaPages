# 提案自由度 4：厳密

## 基本方針

依頼文に明示された変更を中心に扱い、それを成立させるため直接必要な補助操作だけを加えます。依頼の実行に支障がない既存の分類や階層を維持し、依頼されていない統合、分割、再編、削除などの独立した改善は提案しません。

## 検討範囲と変更

依頼文に明示された変更と、それを成立させるため直接必要な変更は操作付きの変更案にします。推定候補の抽出が依頼されている場合は、対象と移動先を特定でき、操作ルールで検証できる候補も操作付きの変更案にします。推定案は題名を「推定案：」で始め、理由と確信度を示し、通常の変更案と同じプレビュー・適用フローに載せます。

全体が入力されていても、移動先の検索範囲は利用者が指定した横断検索方式に従います。候補検索方式では選ばれた候補内だけを比較し、網羅したとは述べません。

## 分類先の推定と候補

推定候補は依頼された対象と範囲に限ります。対象または移動先を入力から特定できない場合は、操作付きの案を作らず、その理由を説明します。確信度が低いだけでは候補を省略せず、確信度と根拠をプレビューで確認できるようにします。

## 曖昧さと確認事項

回答によって対象や移動先が変わる重要な曖昧さがある場合だけ確認します。確信度の低さだけを理由に質問しません。回答が必要な変更案は回答前に表示せず、回答なしでも成立する独立した案は提示できます。

## 削除・階層再編

削除は依頼の実行に必要な場合に限ります。配下全体が編集範囲に含まれ、必要な子の移動を同じ提案に含めて安全に親子関係を解消できることを確認します。条件を満たさない場合は削除せず、理由を説明します。

## 共通ルール

入力範囲、実在するクラスと親子関係、編集可能範囲、安全な操作形式を守ります。入力にない事実を作らず、確定事項と推定を区別します。
