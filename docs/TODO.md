## 管理ルール

- 「直近の確認」には、実装済みで受け入れ確認が残る項目を置く。
- 「次に進めること」には、着手する開発課題を置く。
- 方針が決まっていない項目は「決めること」に置く。
- 実装だけで完了と判断できない場合は、受け入れ確認後に「対応済み」へ移す。

## 現状の実装

- 新AIチャットは、計画・読み取り・提案作成・検証・プレビュー・利用者による適用を行う。
- 計画では依頼内容と件数から処理を判定し、構造設計時は対象範囲の階層データを使う。
- 選択範囲の読み取り、追加範囲の許可、確認質問、進捗表示、予算停止・続行に対応している。
- 末端クラスの移動、一括移動、階層再編、上位・中間クラスの削除を別の処理経路で扱う。
- ジョブのチェックポイント、単位ごとの結果保存、データ版記録、中断後の再開機構がある。
- 提案の検証、競合・代替案の選択、プレビュー、利用者による適用に対応している。
- 会話履歴と段階メモを保持する。後続依頼では条件に応じて対象範囲を引き継ぎ、画面で別範囲を選ぶと切り替える。クラスの事実は毎回現在のデータから取得する。
- 編集画面には階層編集、Undo/Redo、保存前検証、データ読み込み、JSON書き出しがある。

## 次に進めること

### 再編案の段階化

- [ ] 再編を依存関係に沿う段階式の提案にする。
  - [ ] 第1段階で、新設クラスと共通の親子構造を一度だけ準備する。
  - [ ] 第2段階で、実際の移動先の親クラスごとに末端クラスの移動案を分ける。
  - [ ] 第3段階で、必要な移動が完了した後に不要クラスを整理する。
  - [ ] 段階間で仮IDを確定後のIDへ安全に引き継ぎ、前提操作が未適用の案は適用できないようにする。
  - [ ] 各段階の適用・見送り状態を保持し、適用後に残りの案を再検証する。失敗時は編集データを変更せず原因を示す。

### AIジョブと階層編集

- [ ] 特定のクラス名・ルート・再編パターンをコードに固定せず、対象範囲・階層・操作をデータとして扱う。
- [ ] 小規模な相談から大規模な階層編集まで同じジョブ契約で扱い、規模に応じて一括処理と分割処理を選ぶ。
- [ ] 対象ルート、データ版、完了条件、作業単位、進捗、累積予算を一貫して記録し、安全な中断・再開を行う。
- [ ] 対象IDと親子関係を漏れなく確認し、必要な詳細だけを分割取得する。未取得範囲と理由も記録する。
- [ ] 再編の分類骨組みと、各クラスの維持・移動・改名・新設分類への配置・保留を構造化して記録する。
- [ ] 全対象を確認・記録することと、変更案を出すことを分け、妥当な変更候補だけを提案する。
- [ ] 分割結果を統合し、対象漏れ・重複割当・存在しない移動先・階層矛盾・範囲外変更・古いデータ版をアプリ側で検査する。
- [ ] 検査済みの変更を既存の提案・プレビュー・適用へ接続する。
- [ ] 上位・中間クラスの作成・改名・移動・配下再編を共通ジョブで扱う。削除は配下の移動と整合性検査を含め、「未分類」を除外して安全に完了させる。

### 会話の継続

- [ ] 意図が明確な場合は処理を進め、回答に影響する未確定事項を文脈から解消できない場合に確認質問を行う。

- [ ] データ版が変わった場合は過去のクラス情報を事実として再利用せず、現在のデータを確認してから続ける。
- [ ] 質問への回答、評価から変更案への移行、提案の修正を同じ会話の続きとして扱い、提案・合意・適用済みを区別する。

## 対応済み

- AIジョブの工程・単位・結果・データ版を持つチェックポイント形式と、完了単位を飛ばして続行する共通ループを追加した。工程結果を単位ごと・工程全体で検証し、予算停止・中断・データ版変更を記録する。
- 既存クラスの一括移動処理を共通ループへ接続し、対象取得前からジョブ状態と使用量を保存する。通常判定と保留分の再判定も工程として記録する。同じ会話では未完了工程から再開し、明示された別件は新規作業として扱う。対象範囲・データ版・保存済み移動先が変わった場合は続行を止める。
- 対象詳細と階層索引のページごとの取得結果をチェックポイントに保存し、上限停止後は完了ページを取り直さず未完了ページから再開する。ページカーソルはデータ版と位置を含む再生成可能な形式にする。
- ブラウザーでクラス・インスタンスデータとクラス階層データを読み込み、新規作成または現在の作業への追加を選べる。
- 作業データを同じタブ内で保持し、編集データをJSONとして書き出せる。
- AIチャットは変更案を提示し、利用者がプレビューから適用する。
