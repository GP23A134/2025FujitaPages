# 汎用階層データ作成プログラム

## 目的

利用者がデータをアップロードし、AIチャットまたは手動操作でクラス階層を作成・編集し、その結果を出力できるWebシステムを作る。最終的には特定のデータを同梱せず、空の状態から利用を始められるようにする。

## 現在の構成

- 現行Webアプリは共通JSONを読み込み、閲覧・編集し、AIチャットや手動操作で階層を付与する。
- クラス・インスタンス・所属関係を含むデータと、クラス階層データを扱う。階層データは別ファイルでも読み込め、クラスIDで照合する。
- SPARQL取得結果は`data/query-results/`に置き、Javaプログラムで統合・Web表示用データ生成を行う。
- 分類更新JSONは`data/input/`で受け付ける。編集画面は日時付きJSONを出力し、Javaの`ClassDataUpdate`は最新の入力を適用して履歴へ保存する。
- 読み込み画面、AIチャット表示確認、SPARQL結果変換の試作はGit対象外の[`.local-test/`](.local-test/)にある。
- Javaの統合処理とWebデータ生成は`data/integrated/`の4つのJSONを使う。
- ブラウザーのデータ読み込み画面はクラス・インスタンスデータとクラス階層データの2ファイルを受け付ける。ローカルテスト用の現在データは`.local-test/data/current-workspace/`にある。

## 今回の変更

- 編集画面の保存JSONに日時を付ける。
- `ClassDataUpdate`は複数の分類更新JSONから最新の1件を選び、入力検証後に他の分類更新JSONを削除してから、選択したJSONを適用し履歴へ移す。
- `data/input/README.md`と`java/README.md`を新しい入力方法に合わせる。
- 旧`data/import-ready/`の固定データを削除し、SPARQL取得結果を使う構成に整理する。

## 最終的な目標と方針

- 利用者は変換前のデータをアップロードし、Webシステム内で変換・確認した後に作業データとして使う。
- まず現行SPARQL結果JSONを対象に変換仕様を固める。その後、他の入力形式にも対応できるよう変換方法を拡張する。
- クラス・インスタンス・所属関係は一まとまりで扱い、クラス階層は必要に応じて別データとして扱えるようにする。
- 入力にあるIDは保持し、IDがあるデータには新しいIDを提案しない。
- 上位・中間クラスのIDは作成時に自動採番し、接頭辞は階層ごとに設定できるようにする。試作の初期値は上位`t_`、中間`m_`。
- 読み込み時に「新しい作業」と「現在の作業データへの追加」を選べるようにする。
- 元データと作成した階層を合わせて出力し、再読み込みできるようにする。
- 閲覧モードと編集モードは同じデータ状態を扱えるようにする。
- 現行データURL読み込み用の開発者フラグは通常画面から隠し、最終版では固定データとともに外す。
- 認証によるアクセス制御は後で検討する。

## 次に整理・決定すること

### 1. 変換機の仕様

- [ ] 変換前データのアップロードから、変換結果の確認、作業データへの反映までの画面遷移を決める。
- [ ] 現行SPARQLクエリ結果の変数名と、インスタンスID・クラスID・ラベル・所属・階層の対応を確定する。
- [ ] クラス・インスタンス・所属関係をまとめる出力と、階層データを分ける出力の形式を決める。
- [ ] IDなし、ラベルなし、クラス未割り当て、重複、参照切れを表示し、出力可否を決める。
- [ ] 既存IDを維持し、IDのないデータだけに候補を示すルールを決める。
- [ ] 上位・中間クラスの接頭辞設定を、変換後の作業データとクラス作成処理へ渡す方法を決める。
- [ ] `.local-test/`の変換試作で出力を確認し、現在の共通JSON読み込みとの整合を取る。

### 2. Webシステムへの統合

- [ ] 仕様確定後、変換前データのアップロードと変換処理を現行Webシステムへ統合する。
- [ ] 変換結果と例外を確認してから、新しい作業または現在の作業への追加を確定できるようにする。
- [ ] 変換設定と上位・中間クラスのID接頭辞を作業データに保存し、編集時に利用する。
- [ ] Javaの更新・Webデータ生成処理が固定パスの統合JSONに依存せず、アップロードした作業データを受け取れるようにするか、旧Java更新経路を終了するか決める。
- [ ] 元データと編集した階層の出力・再読み込みを一連の操作として扱えるようにする。
- [ ] 閲覧・編集モード間で同じ作業データを共有する。
- [ ] 空の状態を起動時の標準にし、開発用の現行データ読み込み手段を通常UIから分離する。

### 3. クラス・インスタンス編集の拡張

- [ ] インスタンス単位で対象クラス階層を編集できるようにする。
- [ ] クラス未割り当てインスタンスの確認、対象クラスの作成、割り当ての流れを設計する。
- [ ] 対象クラスとインスタンスの編集に適した専用画面を検討する。

### 4. AIチャット表示

- [x] テスト画面に現行表示、代替案、変更前後のプレビュー、フォントサイズ調整を用意した。
- [ ] ツリーと矢印の位置・重なりを通常幅と狭い画面で確認する。
- [ ] 比較結果をもとに表示方法を決め、現行システムへの反映またはテスト画面の整理を行う。

## テストスペース

- `.local-test/data-upload.html`：共通JSONの読み込み・表示確認。
- `.local-test/data-converter.html`：SPARQL結果JSON変換の試作。
- `.local-test/ai-chat-preview.html`：AIチャット要素と表示状態の確認。
- `.local-test/index.html`：テスト画面の入口。
- `.local-test/README.md`、`.local-test/start.ps1`：起動・利用方法。
- `.local-test/`は`.gitignore`で除外し、テスト画面とコピーしたデータはGitに含めない。
