## 優先度の付け方

- 「現在対応すること」は作業中・次に着手する項目に絞る。
- コード上実装がある項目でも、受け入れ確認が必要なら「対応済み」には移さない。
- 完了を確認した項目は「対応済み」に移し、方針未決定の項目は「決めること」に置く。

## 現状の実装（受け入れ確認は別途）

- 新AIチャットは、計画・読み取り・提案作成・検証・プレビュー・利用者による適用の処理を持つ。
- 計画では依頼内容と件数から必要な処理を判定し、構造設計が必要な場合は対象範囲の階層データを使う。
- 選択範囲の読み取り、追加参照・変更範囲の許可、確認質問、処理進捗、予算停止・続行の仕組みがある。
- 末端クラスの移動、一括移動、階層再編、上位・中間クラスの削除は、それぞれ別の処理経路として実装されている。
- ジョブのチェックポイント、単位ごとの結果保存、データ版の記録、中断後の再開機構がある。
- 提案の検証、競合・代替案の選択、プレビュー、利用者による適用がある。
- 会話履歴と段階メモを保持する。同じ会話の後続依頼では条件に合う場合に対象範囲を引き継ぎ、画面で別の範囲を選ぶとそちらを使う。新しい会話では文脈を切り替える。
- クラスの事実は各依頼で現在のデータから取得する。前の会話から対象や方針を引き継ぐ仕組みと、事実を再確認する仕組みは分かれている。

## 現在対応すること

### 会話のやり取り

- [ ] 回答に影響する未確定事項が文脈から解消できない場合だけ確認質問を行う。意図が明確なら処理を進め、妥当な前提を置く場合はそれを示す。
- [ ] 同じ会話で前の対象・候補・合意・提案状態を自然に参照できるようにする。画面で別のクラスを選択した場合や依頼文で別の対象が特定された場合は対象を切り替える。
- [ ] データ版が変わった場合は、前のクラス情報を事実として再利用せず、必要な範囲を現在のデータで確認してから続ける。
- [ ] 質問への回答、評価から変更案への移行、提案の修正などを、同じ会話の続きとして扱う。提案・合意・適用済みを区別する。

### AIチャットのジョブと階層編集

- [ ] 特定のクラス名、ルート、再編パターンをコードへ固定せず、対象範囲・階層・利用可能な操作をデータとして扱う。具体例は専用分岐ではなく受け入れ確認に使う。
- [ ] 小規模な相談から大規模な階層編集までを同じジョブ契約で扱い、規模に応じて一括処理か分割処理かを選ぶ。
- [ ] ジョブの対象ルート、データ版、完了条件、作業単位、進捗、累積予算を一貫して記録し、安全に中断・再開できるようにする。
- [ ] 対象IDと現在の親子関係を漏れなく確認し、必要な詳細だけを分割取得する。未取得範囲と理由を記録する。
- [ ] 再編の分類骨組みと、既存クラスごとの維持・移動・改名・新設分類への配置・保留を構造化して記録する。
- [ ] 全対象を確認・記録することと、全対象へ変更案を出すことを分ける。妥当な変更候補だけを提案する。
- [ ] 分割結果を統合し、対象漏れ・重複割当・存在しない移動先・階層矛盾・範囲外変更・古いデータ版をアプリ側で検査する。
- [ ] 検査済みの変更を既存の提案・プレビュー・適用へ接続する。
- [ ] 上位・中間クラスの作成・改名・移動・配下再編など、階層変更全般を共通ジョブで扱う。クラス削除は配下の移動と整合性検査を含む専用ジョブとして安全に完了させる。「未分類」は削除対象から除外する。
- [ ] 代表例として、「未分類」配下から複数の上位クラスを新設して振り分けるケース、既存サブクラスを再編するケース、既存・新設クラスへの移動案を作るケースを確認する。
- [ ] 各代表例で、件数に応じた一括・分割処理、全対象の確認記録、妥当な候補だけの提案、提案統合、予算停止後の続行を確認する。
- [ ] 大規模な受け入れ例として、「未分類」配下の約1万件を新設する複数の上位クラスへ割り当て、作成・移動・全件検査・安全な適用まで確認する。

### 範囲・上限・進捗

- [ ] 依頼の対象範囲、参照範囲、変更可能範囲を計画時に分けて示す。
- [ ] 追加範囲の許可時に、対象・参照か変更か・件数・続ける処理を確認できるようにする。
- [ ] 許可・拒否・キャンセル・許可後も範囲不足の状態を区別し、表示と実際の処理結果を一致させる。
- [ ] 許可済み範囲と取得結果を記録し、同じ処理の再開時に不要な再取得を避ける。
- [ ] 取得回数、AI応答回数、入力・出力トークン、再計画、概算費用、経過時間を工程別・依頼全体で把握する。
- [ ] 上限停止時に進捗を保存し、完了範囲・未処理範囲・続行に必要な量を示して安全に再開する。
- [ ] 計画中・取得中・分析中の表示を実際の処理に合わせ、未確認の内容を確認済みのように表示しない。
- [ ] 範囲許可、上限到達、続行、拒否・キャンセルを含む一連の受け入れ確認を行う。

### 提案とプレビュー

- [ ] 競合案を一覧で確認できるようにし、案の状態・変更概要・プレビュー操作を分かりやすくする。
- [ ] 競合案の選択と通常案のページ移動を区別する。
- [ ] 競合グループの一案を適用した後、ほかの案を適用できないことを示す。
- [ ] 競合案と独立して適用できる案を区別する。
- [ ] 検証済みの階層再編案を変更後の親クラスごとに分割する。親の新設・改名と配下の配置変更など依存操作は同じ案に束ね、個別適用・見送りの進捗を保持する。適用後に残りを再検証し、失敗時は編集データを変更せず原因を示す。

### 旧AIチャットの終了

- [ ] 旧AIチャットから新AIチャットへ移行が必要な機能・データを確認する。
- [ ] 旧AI送信処理に残る未使用のプロンプト生成コードと関連設定を整理する。

## 対応済み

- AIジョブの工程・単位・結果・データ版を持つチェックポイント形式と、完了単位を飛ばして続行する共通ループを追加した。工程結果を単位ごと・工程全体で検証し、予算停止、中断、データ版変更を記録する。
- 既存クラスの一括移動処理を共通ループへ接続し、対象取得前からジョブ状態と使用量を保存する。通常判定と保留分の再判定も別工程として記録する。同じ会話の次の依頼では、特定の続行語句なしで未完了工程から再開し、明示された別件は新規作業として扱う。対象範囲・データ版・保存済み移動先が変わった場合は続行を止める。
- 対象詳細と階層索引のページごとの取得結果をチェックポイントに保存し、上限停止後は完了ページを取り直さず未完了ページから再開する。ページカーソルはデータ版と位置を含む再生成可能な形式にする。
- ブラウザーでクラス・インスタンスデータとクラス階層データを読み込み、新規作成または現在の作業への追加を選べる。
- 作業データを同じタブ内で保持し、編集データをJSONとして書き出せる。
- AIチャットは変更案を提示し、利用者がプレビューから適用する。
